# 工作标签

issue 标签分两类：三组待办标签（影响面、急迫度、负责），以及一组分类标签。两类全部用中文。完整口径见 `_规范/待办/README.md`。

## 影响面

| 标签 | 含义 |
| --- | --- |
| `核心` | 这一项不补会卡住跨区接口、整段剧情或专名的首次出现 |
| `重要` | 这一项不补，本区写不完、写不顺，但不会挡住别的区 |
| `补充` | 这一项只补专名与细目，不会挡住别的区 |

## 急迫度

| 标签 | 含义 |
| --- | --- |
| `急` | 这一项阻塞整段剧情或跨区接口，可以打断当前工作先办 |
| `高` | 这一项这一轮就要写定，不写没法往下走 |
| `中` | 这一项排进最近几轮再写 |
| `低` | 这一项有余力时再写 |

## 负责

| 标签 | 含义 |
| --- | --- |
| `作者` | 作者拍板决定设定取舍、因果与专名 |
| `编辑` | 编辑在既有框架内补写内容，并统一说法 |
| `智能体` | 智能体先写草稿，作者验收 |
| `待核实` | 这条事实与正史是否冲突还没确认，确认之后再谈怎么写 |

## 分类

这一组标签说明 issue 本身是哪一类问题，与上面三组可以同时使用。本仓库当前 168 条待办都只打三组待办标签，还没有用到分类标签。

| 标签 | 含义 |
| --- | --- |
| `缺陷` | 已有内容出错，与设定或约定不符 |
| `文档改进` | 补充或修正文档内容 |
| `新功能` | 提出新的功能或改进请求 |
| `疑问` | 还需要补充信息才能回答 |
| `重复` | 这个问题或请求已经登记过 |
| `不成立` | 这个问题本身不成立，不需要处理 |
| `不修` | 这一项确定不处理 |
| `适合新手` | 上手容易，适合第一次参与的人处理 |
| `需要帮助` | 这一项需要其他人一起处理 |

## 使用规则

- 待办标签三组各打**一个**，不多打、不漏打。
- 分类标签按需打，可以不打；一条 issue 最多打一个分类标签。
- 状态不设标签：开着是没办完，关掉是办完了。
- 标签与本地表一致；改标签后跑 `python _规范/工具/同步索引.py` 重建表。
- 本仓库不接收外部提交的 issue，因此不设「待分诊」这类状态标签。万一收到外部 issue，先由作者判断属于哪一类，再按上表打标签。
