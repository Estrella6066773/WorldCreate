# 领域文档

engineering skills 探索本仓库时，按这里的规则读取领域文档。

## 探索前先读这些

- 仓库根目录的 **`GLOSSARY.md`**：本设定库的术语正本。每个术语都带 `_Avoid_:` 行，列出已废弃的说法与等式。
- **`docs/adr/`**：读取与本次要改的区域相关的决策记录。

本仓库是 single-context，没有 `GLOSSARY-MAP.md`，根目录一个 `GLOSSARY.md` 就够。

`docs/adr/` 目前还不存在，这是正常的。**静默继续，不要提示缺失，也不要提前建议创建。** `/domain-modeling` skill（由 `/grill-with-docs` 和 `/improve-codebase-architecture` 调用）会在第一个决策真正定下来时按需创建。

## 文件结构

```
/
├── GLOSSARY.md     已决议词汇，写故事时不能改口的术语正本
├── docs/
│   ├── agents/     本目录：agent 配置
│   └── adr/        决策记录（按需创建）
├── 词条/            设定词条，按时间／地点／参与者／事件存放
├── 分支时间线/      分支叙事与时间线
├── 绘图/            设定向绘图说明
├── 草稿/            草稿与溯源
├── 00-总览/         导读 · 知情对照 · 母设定待定
└── 总世界线.md      总览索引
```

## 使用 glossary 的词汇

输出里命名某个概念时（issue 标题、改写提议、假设、测试名），使用 `GLOSSARY.md` 里定义的术语。不要漂移到 glossary 明确避免的说法。

需要的概念还不在 glossary 里，这是一个信号：要么你正在发明本库没在用的语言（回头重新想），要么确实存在缺口（留给 `/domain-modeling` 记录）。

## 标记 ADR 冲突

输出与现有 ADR 矛盾时，直接指出来，不要静默覆盖：

> _与 ADR-0003（某条决策）矛盾，但值得重开，因为……_
