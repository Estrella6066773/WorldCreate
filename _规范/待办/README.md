# 待办 · 口径

| 字段 | 内容 |
|------|------|
| 状态 | 现行 |
| 最后更新 | 2026-11-08 |
| 适用范围 | 全库未办结项：母设定、云上坟场、击魄 |

## 一句话

**条目本体是 GitHub issue。** 本地 `待办/*.md` 只是从 issue 生成的一张表，供扫读用，**不要手工编辑**。

## 两层

```
GitHub issue（168 条）       记录：可关闭、可评论、可搜索、带标签
        │  同步索引.py 拉取
本地 待办/*.md               视图：按影响面排好的一张表，带 issue 号
```

| 层 | 负责什么 | 改法 |
|----|----------|------|
| issue | 这件事是什么、缺什么、怎么算做完 | 网页或 `gh` 增删改 |
| 本地表 | 一眼看到还有哪些事、按影响面排序 | 跑脚本重建，不手写 |

登记号与来源文件记在 `_规范/待办/issues.json`，由导入脚本写入。这个文件也不要手改。

## 三列标签

issue 上打三组标签，与本地待办表的三列一一对应：

| 组 | 取值 | 回答什么 |
|----|------|----------|
| 影响面 | `核心` / `重要` / `补充` | 补慢了会挡住什么 |
| 急迫度 | `急` / `高` / `中` / `低` | 这一轮要不要写定 |
| 负责 | `作者` / `编辑` / `智能体` / `待核实` | 谁能动手写 |

### 影响面

| 取值 | 判据 |
|------|------|
| **核心** | 这一项不补会卡住跨区接口、整段剧情或专名的首次出现 |
| **重要** | 这一项不补，本区写不完、写不顺，但不会挡住别的区 |
| **补充** | 这一项只补专名与细目，不会挡住别的区 |

### 急迫度

| 取值 | 判据 |
|------|------|
| **急** | 这一项阻塞整段剧情或跨区接口，可以打断当前工作先办 |
| **高** | 这一项这一轮就要写定，不写没法往下走 |
| **中** | 这一项排进最近几轮再写 |
| **低** | 这一项有余力时再写 |

### 负责

| 取值 | 含义 |
|------|------|
| **作者** | 作者拍板决定设定取舍、因果与专名 |
| **编辑** | 编辑在既有框架内补写内容，并统一说法 |
| **智能体** | 智能体先写草稿，作者验收 |
| **待核实** | 这条事实与正史是否冲突还没确认，确认之后再谈怎么写 |

状态不设标签：issue 开着就是没办完，关掉就是办完了。起草中的过程写在 issue 评论里。

## 查询

实测口径（2026-11-08 在本仓库验证过）：

| 查询方式 | 是否可用 | 说明 |
|----------|----------|------|
| 中文词（两个字以上） | ✅ | 标题与正文都索引，如 `未保存保护` |
| 混排专名 `A 站` / `巨企N` / `离散AI` | ✅ | 全部命中 |
| 单个汉字 | ❌ | 不索引，检索至少用两个字 |
| 标签过滤 | ✅ | 新建标签有几秒索引延迟 |

常用命令：

```powershell
# 核心项，按影响面筛
gh issue list -R Estrella6066773/WorldCreate --label 核心

# 交给智能体、急迫度为高的
gh issue list -R Estrella6066773/WorldCreate --label 智能体 --label 高

# 关键词 + 标签
gh issue list -R Estrella6066773/WorldCreate --search "label:作者 巨企N"

# 全部未关闭，按创建时间正序
gh issue list -R Estrella6066773/WorldCreate --limit 300 --search "sort:created-asc"
```

网页上等价写法：在 issue 列表搜索框里填 `is:open label:核心`。

**记住一点**：issue 列表一页 25 条，168 条要翻 7 页，且不能按影响面排序。**看全貌用本地表**，检索才用搜索。

## 新增一条

1. 先检索：「这条是不是已经有了」。搜两个字以上的关键词；已有就在那条 issue 补 `## 来源` 与 `## 详情`，不新开。
2. 新建 issue，标题写清缺什么，不写「待定」「待补」这类空词。
3. 正文按下面的骨架写。
4. 打三组标签。
5. 跑 `python _规范/工具/同步索引.py` 重建本地表。

### 正文骨架

```markdown
## 来源

- [词条/参与者/势力/矿业联盟.md]（仓库内绝对链接）
- 原登记于 `_规范/待办/参与者.md`，添加时间 2026-08-29

## 详情

缺什么、依赖什么、为什么难。

## 验收

- 改动涉及的文件说法一致，不出现两套定义
- 专名与 GLOSSARY.md 一致，不新增未决议词
- 相关词条与总览的链接可点开
```

来源里的文件链接**必须用仓库绝对地址**（`https://github.com/Estrella6066773/WorldCreate/blob/master/...`），相对路径在 issue 页面点不开。

## 办结一条

1. 验收。设定库没有脚本验收，判据是：**改动涉及的文件是否一致、术语是否回到 `GLOSSARY.md`、知情分层是否标对、交叉引用是否补齐**。
2. 关闭 issue，写一条评论：

```markdown
验收通过，提交 <sha>。

**改动**
- 某词条补了某某设定

**验收**
- `GLOSSARY.md` 未新增未决议词
- 相关词条与总览的链接都能点开
```

3. 跑 `python _规范/工具/同步索引.py`，那一行会自动从本地表消失。

**办结即出库。** 表里不保留已关闭项；历史在 GitHub 的 closed 列表和 `git log` 里。

## 工具

| 脚本 | 用途 |
|------|------|
| [`_规范/工具/导入待办.py`](../工具/导入待办.py) | 从本地表批量建 issue。已登记过的会跳过，可重复跑 |
| [`_规范/工具/同步索引.py`](../工具/同步索引.py) | 从 issue 重建本地表。**唯一允许修改 `待办/*.md` 的方式** |

两个脚本都要在仓库根目录执行，且需要 `gh` 已登录。

## 文件划分

母设定按词条的存储轴切：

| 文件 | 收什么 |
|------|--------|
| `时间.md` | 时代先后、年份、时序 |
| `地点.md` | 天体、地表、轨道、以太界、云城的专名与布局 |
| `参与者.md` | 族群、势力、人物、污染、至高存在、机魂 |
| `事件.md` | 跨区的「谁对谁做了什么」 |
| `概念.md` | 跨线使用的抽象概念、机制 |
| `跨区.md` | 不落在单一轴上的跨区治理与接口 |

子设定集各自建 `00-总览/待办/`，按本集的线切分（明线／暗线／美术）。**子集的条目不进母设定的表**，母设定也不代子集登记。

## 禁止

- 手工编辑 `待办/*.md` 或 `issues.json`。要改就改 issue，再跑脚本。
- 在正文、总览、时间线里另开待定清单（`- [ ]`、`待定` 小节都算）。
- 同一件事开两条 issue。
- 用「待定」「待补」「后续再说」当 issue 标题的全部内容。
- 只打影响面不打负责（或反之）。三组标签缺一，表里就是空白格。
