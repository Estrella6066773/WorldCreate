# 词条写作规范

## 视角要标出来

同一个主题在库里可以同时有几种说法：某派系自己怎么讲、外界怎么传、设定上实际是什么。写作时**分开写，标明视角**，不让读者自己去猜哪句是真的。

| 视角 | 用法 |
|------|------|
| 圈内叙事 | 某派系、职阶、时代人物的自认或正典所述 |
| 圈内传闻 | 未证实、众说纷纭，明写「众说纷纭」「据说」 |
| 设定真相 | 作者定稿，可与圈内叙事冲突 |

禁止把设定真相直接写进玩家可见文案。玩家向说明只用圈内可见内容。

## 专名

- 专名的正本是 [GLOSSARY.md](../GLOSSARY.md)。写作前先查，`_Avoid_` 里列出的旧说法一个字都不要用。
- 同一实体在一篇文档里只用一种称呼。发现两种叫法并存时，统一成 GLOSSARY 里的那个，并在待办里登记该统一动作。
- 不在正文里自造简称、缩写、压缩词。两个意思各自能成词时，写成两个完整词（「安全策略」而不是拼字）。

## 结构与篇幅

- 章节顺序：概述 → 特征 → 历史演变 → 关系 → 待定。
- 概述一节回答「这是什么」，不复述历史。
- 历史演变按时间分段，每段一个二级或三级标题。
- 关系一节只写与谁有关系、关系是什么，不展开对方的内部设定；需要展开时给链接。

## 待定不写在正文里

正文不列 `- [ ]` 待定清单，也不开「待定」「待细化」的条目小节。只写一行：

```markdown
## 待定

未办结项统一登记在 [参与者.md](待办/参与者.md)。
```

条目本体登记在对应 `待办/` 文件。口径见 [待办/README](待办/README.md)。

## 交叉引用

- 链到最具体的文件。子区已有自己的 `README.md` 时，不要只链到父级总览。
- 地点类条目遵循「一地点一文件夹 + `README.md` 为唯一主文件」，见 `.cursor/rules` 里的地点规范。
- 跨区引用只引对方已写在外的接口；对方内部设定不要搬进本区正文。

## 属性

元数据写在文首的属性块里，正文不写页脚：

```markdown
---
分类:
  - 参与者
  - 势力
  - 联盟
时代:
  - 大灾变前
  - 灾后
  - 环带内战
  - 亚冷战
  - 抗击异魔
状态: 存续（环带内战参战方）
---
```

`状态` 不只写「已完成」「进行中」；要写出这个世界里实体是什么状态，或这篇文档的完整度。字段写法见 [文档维护与版本策略](文档维护与版本策略.md)。
