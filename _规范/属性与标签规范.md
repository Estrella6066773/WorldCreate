# 属性与标签规范

本文件规定每条文档在文首属性块里写什么、取值从哪来、`标签` 怎么用。字段的机器可读取值表在本文末尾的 YAML 区块，检查脚本直接读这一段，**不要另建一份词表**。

## 问题：一个字段装了五个维度

`分类` 这一个字段同时装着五类东西：

| 装进去的东西 | 例子 |
|---|---|
| 文档类别 | 词条、索引、总览、规范、草稿 |
| 存储轴 | 参与者、地点、事件、时间、概念 |
| 实体子类 | 势力、族群、人物、污染、至高存在 |
| 叙事层 | 明线、暗线、真相、背景 |
| 归属集 | 云上坟场、击魄、母设定、子设定 |
| 主题与时期 | 伊勒信仰、路西法、灾变时代、前史 |

一个字段装五类值，取值就无法受控。当前 237 篇文档的 `分类` 一共出现 174 个不同取值，其中 110 个只出现过一次。取值失控带来三个具体后果：

1. **跨维度冲突。** 同一个实体在两处被判成不同子类。`云上人` 在母设定按路径属于 `参与者/族群`，属性却写 `势力`；副标题又写「存在形式」。
2. **与路径重复，改一处就落后。** `参与者`、`明线`、`云上坟场` 这些值，路径里已经写过一遍。路径改名时属性不跟着改，两处必然分叉。
3. **同一维度混进另一个维度。** `昏昼` 的属性把 `灾变时代` 写进 `分类`，而 `时代` 字段里又写了一遍。

## 分三层，一个维度只住一层

每个维度只挑一个地方存放。选了路径就不写属性，选了属性就不写标签。

| 层 | 承担哪些维度 | 为什么放在这里 |
|---|---|---|
| **路径** | 存放位置、存储轴、实体子类、叙事层 | 路径已经在承担这些。Obsidian 改名或移动文件时会同步改写链接，属性不会。 |
| **属性** | `类型`、`文档状态`、`故事线`、`时代`、`状态` | 路径推不出这几个。属性可排序、可筛选、可建视图。 |
| **标签** | 主题、核实状态、来源标记 | 交叉维度与临时标记，一个文档可以挂多个，不占轴。 |

判断一个维度该放哪，只问一句：**把它从文件属性里删掉，信息是否还在？** 路径已经写着「参与者/势力」，删掉属性里的 `势力` 不丢信息，所以它属于路径。

有两处是这条判据的例外，写在这里免得下次再吵一遍：

- **`故事线`。** 它记录的「哪几条线用到这一篇」，路径推不出来。跨故事层的词条（地点、事件、接口页）可以只存在 `词条/` 下，却被多条分支线引用。
- **`类型`。** 它记录的是文档在库里的角色（词条、索引、草稿、模板），同一个目录下可以并存不同角色，路径定不了。

## 属性字段

### 六个固定字段

| 字段 | 回答什么 | 取值来源 |
|---|---|---|
| `类型` | 这是一份什么文档 | 受控，见文末词表 |
| `文档状态` | 这篇文档能不能被引用 | 受控，见文末词表；只用于词条、分支正文、规范、索引 |
| `故事线` | 哪几条分支线在用这一篇 | 受控，见文末词表；只用于词条 |
| `时代` | 内容落在哪一段 | 受控，见文末词表 |
| `状态` | 这个世界里该实体或事件处在什么状态 | 受控，见文末词表；只用于实体与事件 |
| `tags` | 交叉主题与标记 | 见下节「标签」 |

`最后更新` 仍按 [文档维护与版本策略](文档维护与版本策略.md) 写日期。

### 词条随故事走：一事实一权威

`词条/` 是跨故事层，只放四类东西：时间轴、地点坐标、事件、以及跨故事接口页。**单故事的人物、势力、族群、概念、制度不放在这一层**，它们写在 `分支时间线/<故事>/词条/` 下，跟着故事走。

拆分的理由不是归类好看，是**权威**。一个设定事实只由一篇文档负责，改口时只有一个地方要改，引用方链接过去即可，不必各自抄一份。

| 层 | 放什么 | `故事线` 写什么 |
|---|---|---|
| `分支时间线/<故事>/词条/` | 该故事独有的人物、势力、族群、概念、制度 | 本故事 |
| `词条/地点/` | 天体、地表、轨道、云城等共用空间坐标 | 引用它的故事（可多值） |
| `词条/事件/` | 跨区「谁对谁做了什么」，单篇锚在发起区 | 参与该事件的故事 |
| `词条/时间/` | 时代先后 | 通常 `通用` |
| `词条/参与者/`、`词条/概念/` | 只留接口页与真正通用的概念 | `通用` |

同一事物在不同故事里事实不同时，**写成多篇，各在各的故事目录**。以 `异魔` 为例：

| 文档 | 权威范围 |
|---|---|
| [词条/参与者/污染/异魔.md](../词条/参与者/污染/异魔.md) | 跨故事接口：各故事称呼对照，不写经过 |
| [马尔斯·异魔](../分支时间线/马尔斯/词条/参与者/污染/异魔.md) | 起源：穿越机、伪人格化、封存与泄露 |
| [法厄同·异魔](../分支时间线/法厄同/词条/参与者/污染/异魔.md) | 外溢而来、感染与重构机制 |
| [击魄·异魔指挥官](../分支时间线/法厄同/击魄/02-暗线/03-参与者/污染/异魔指挥官.md) | 大群核心的职责与敌意结构 |
| [泰拉·异魔（渊魔）](../分支时间线/泰拉/地面/诸城所在之地/词条/参与者/污染/异魔（渊魔）.md) | 坠入地下成深渊、渊魔、魔王 |

多篇同名不是冲突，只要各归一个不同故事。检查脚本把「同一故事里两份同名」和「跨故事同名」分开报，后者不报错。

### 故事线是路径的断言，不是路径的副本

路径已经写着这一篇存在哪里。`故事线` 不重复这件事，它回答的是**哪几条分支线在正文里用到这一篇**。两件事多数时候一致，在不一致的地方才显价值：`法厄同·词条/地点` 下的一处坐标，路径只说明它在法厄同，而 `环带前史`、`云上坟场`、`击魄` 三条线都在用。

写法四条：

1. **纯名，不放链接。** 属性里出现相对路径，文件一移动就断，视图也无法按它筛选。链接写在正文里。
2. **多值按主线先后排。** 跨故事层的词条（地点、事件、接口页）被两条线用到就写两个值，不写「等」「若干」。
3. **故事目录下的词条只写本故事。** 写在 `分支时间线/<故事>/词条/` 下，`故事线` 却列着别的故事，说明这篇没有搬干净，或者该拆成两篇。
4. **与路径矛盾时以路径为准。** `故事线` 只允许比路径**多**，不允许写出一条被路径排除掉的线。`词条/地点/泰拉/...` 下的一篇写了 `击魄`，就是错，检查脚本会报出来。

只有 `词条` 写这个字段。分支正文的归属由所在目录决定，写了等于复制路径；索引、规范、草稿不是被引用对象，不写。

跨线共用、不属于任何单条线的词条（以太、时代）写 `通用`。

### 类型的判据

`类型` 只有一个值，不许写成列表。判不出来时按下面两条走：

| 情形 | 判为 |
|---|---|
| 有成段的叙事或说明正文，即使它同时挂着子目录索引 | `词条`／`分支正文` |
| 只有目录、链接表、导航，没有独立正文 | `索引` |

地点主文件（`词条/地点/**/README.md`）是该地点的正文，一律写 `词条`。子设定集里的地点切面（`击魄/01-明线/02-地点/舞台/README.md` 一类）也是正文，同样写 `词条`，不因为它叫 README 就写 `索引`。

`规范` 只给仓库级约定用：`_规范/`、`docs/agents/`、仓库根部的 `AGENTS.md` 与 `GLOSSARY.md`。**世界里成文的规则、禁令、法理界定不是 `规范`**，它们是设定正文，写 `分支正文`。这一条最容易判错，因为两者在中文里都叫「规范」。

`_templates/` 下的一律写 `模板`，不写 `文档状态`：模板是被复制的东西，不是被引用的东西。

### 文档状态与状态必须分开

`状态` 原本同时回答两个问题：实体在不在，文档写没写完。于是「活跃」「骨架已立」「接口已定」「随决议更新」「2026-11-08 改为导航页」混在一列。现在拆成两个字段，各答一个：

| 问题 | 字段 | 取值 |
|---|---|---|
| 这篇文档能不能引用 | `文档状态` | `现行` / `待补` / `骨架` / `存档` |
| 这个世界里该实体还在不在 | `状态` | `存续` / `已消亡` / `已中断` / `已发生` / `未定` |

- `现行`：内容与本库其他部分一致，可以引用。
- `待补`：结构完整但有明确缺口。缺口必须登记在对应 `待办/` 里。
- `骨架`：只立了接口，正文没写；或者正文已写，但它的核心因果还挂在未决的核心议题上，定下来之前不能当定论引用。
- `存档`：不再参与现行规则，仅供追溯。

`状态` 只用于实体与事件：人物、族群、势力、地点、制度、机制写 `存续`／`已消亡`／`已中断`；事件写 `已发生`；还没定的写 `未定`。索引、规范、草稿这类文档没有世界内状态，不写 `状态`。

`文档状态` 只给可被引用的文档写：`词条`、`分支正文`、`规范`、`索引`。`草稿`、`原文`、`绘图` 不参与这一轴——它们本来就不是引用对象。落在 `归档/` 下的一律写 `存档`。

细节不进受控字段。原先把「存续（A 站技术官僚）」整个写进 `状态`，现在改为 `状态: 存续` 加 `状态说明: A 站技术官僚`。`状态说明` 是自由字段，不参与筛选，但信息不丢。

### 时代只有一套刻度

各区年表不对齐（见 [词条/时间/时代.md](../词条/时间/时代.md)），但灾难是同一个：母设定叫 `大天灾`，地面宗教叫 `大洪水`，云上坟场叫 `大灾变`。同一个事件不并列三种名字，受控词表里只收 `大天灾`。

| 刻度 | 取值 |
|---|---|
| 灾难之前 | `前文明末期`（地上）、`大灾变前`（法厄同） |
| 灾难本身 | `大天灾` |
| 灾难之后 | `灾后` |
| 法厄同后续 | `环带内战` → `僵持` → `抗击异魔` |
| 地上后续 | `灾变时代` → `节点城时代` |
| 跨越多段 | `贯穿` |

分支集里的相对说法一律换成上面的绝对名，不再写 `战前`／`战时`／`战后`：

| 分支集用词 | 换成 |
|---|---|
| 战前（环带大战之前） | `灾后` |
| 战时 | `环带内战` |
| 战后 | `僵持` |

同一份文档跨多段时写列表，按时间先后排列。`时代` 是唯一按顺序读的字段。

每个阶段名是什么意思，只写在 [GLOSSARY.md](../GLOSSARY.md) 里，本文不重复定义。`僵持` 是专名而非普通描述，别按字面读成势均力敌：它的落点是双方因物资吃紧打不动了，不是休战，也不是完全没有战事，小规模冲突仍在。旧称「亚冷战」已废，归档草稿里仍会看到。

### 自由字段

下列字段只用于人读，检查脚本不校验，也不参与视图筛选：

`相关原文`、`英文工程名`、`范围`、`基于`、`导读`、`状态说明`。

需要补一个自由字段时，先确认它不属于上面六个受控字段中的任何一个。

### 别名必须用 Obsidian 认的字段名

别名写 `aliases`，不写 `别名`。Obsidian 只解析 `aliases`／`alias`：写了它，同一个实体的旧称、简称、英文名在链接自动补全和全库搜索里都会命中；写成中文的 `别名`，那只是一个普通属性，Obsidian 不看。

`aliases` 只收**指同一个东西**的名字：简称、全称、英文定名、仍在用的旧称。不要放 `_Avoid_` 里的废弃说法——那是要禁用的词，放进 `aliases` 会让它继续被补全出来。

```yaml
aliases: [云邦, 云城邦联, Orbis, CCC]
```

## 标签

标签写在 `tags` 属性里，用斜杠分级。只开三组：

| 组 | 用途 | 取值 |
|---|---|---|
| `主题/…` | 跨篇的母题，一个文档可挂多个 | 受控，见下节 |
| `核实/…` | 待办与核实状态 | `核实/待补`、`核实/未定名`、`核实/待核` |
| `来源/…` | 内容来路 | `来源/草稿`、`来源/外部设定` |

约束四条：

1. **标签只写属性写不下的东西。** 类型、时代、归属、子类各有归属，不用标签重复。
2. **`主题/` 的后半段用完整说法。** 不写缩写，不写两个词各取一字拼成的词。
3. **`核实/` 与待办的关系。** 有明确缺口时登记 GitHub issue，标签只作检索入口，不替代 issue。
4. **不写裸标签。** 每个标签都要带组前缀。裸写 `地点`、`势力` 这类词，等于把它当成第六个维度用，而那个维度已经归路径管了；检查脚本会报出来。

### 主题词表

主题是唯一能横切其余五个维度的东西：它不受分区、时代、文档角色约束，所以它必须最紧。词表封闭，新增取值先改这里。

| 主题 | 收什么 | 不收什么 |
|---|---|---|
| `人的界定` | 谁算人：云上人、人工智能、机魂、驾驶员、克隆人、人格化人工智能 | 上传的技术过程（→`意识与备份`）；谁有授权（→`技术授权`） |
| `意识与备份` | 思维上传、意识以太化、复活、备份、换件不换魂 | 谁有资格上传（→`人的界定`） |
| `污染与异化` | 异魔、渊魔、腐化、穿越机污染、无人系统异化为智能体 | 污染引发的政治后果（→`失联与自治`） |
| `信仰与神性` | 伊勒、巴力、天使、荒野信仰、灵界至高存在、源质实体被神格化 | 教派的政治站队（→`技术授权`、`失联与自治`） |
| `以太与航道` | 以太的性质、以太界、航道失效与锚点航行、麦哲伦号 | 「以太是能源」——本库否定这一说法，不要把误说写成标签 |
| `技术授权` | 谁有权放行技术：一次交付、官方授权、准入信物、封存修剪 | 技术原理本身 |
| `失联与自治` | 分区失联后分头生存、地方自治、云邦收缩、边缘区独立 | 战争过程（→事件词条） |
| `圈内称谓` | 同一事物各地不同叫法，以及圈内叙事与设定真相的落差 | 单纯的别名（→`aliases`） |
| `执火` | 执火者、执火军、昏昼、纳光为火、执火者旧占领区 | 没有被执火意象收编的一般反抗 |

一条判断：**如果一篇文档挂不上任何主题，就不挂。** 主题不是必填项，空着比凑一个更诚实。

`主题/` 只在真的被多篇共用时才有意义——只在一篇里说的东西，是那篇的内容，不是主题。

## 冲突怎么裁

同一维度被两处同时声明时，按顺序裁：

1. **路径优先。** 路径写 `词条/参与者/族群/`，属性写 `势力`，以路径为准，删掉属性里的子类。`故事线` 与路径矛盾时同样以路径为准：路径排除掉的线不许出现在 `故事线` 里。
2. **母设定优先。** 同一实体在母设定与子设定各有一份时，子设定不声明 `时代` 与 `状态` 的母设定口径，只写本集时点。`时代` 可写，但必须是受控取值。
3. **标签最弱。** 标签与属性冲突时，删标签。

裁定完成后，被删掉的说法不再出现在任何属性里。正文里仍可按视角写不同说法，那是 [知情对照表](../00-总览/知情对照表.md) 管的事。

## 迁移：`分类` 的去处

`分类` 退休，不再新写。现有取值按下面四条分流：

| 取值类型 | 去哪 |
|---|---|
| 文档类别（词条、索引、总览、规范、草稿、导读、待办） | 写进 `类型` |
| 存储轴、实体子类、叙事层、归属集（参与者、势力、明线、击魄…） | 删除，路径已经表达 |
| 时代（灾变时代、前史、战后） | 写进 `时代`，按受控取值改写 |
| 主题（伊勒信仰、路西法、执火叙事、灵界称谓） | 写进 `tags`，加 `主题/` 前缀 |

迁移过程中同一实体出现两种子类时，按上文「冲突怎么裁」的路径优先处理。

## 检查

```powershell
python _规范/工具/查属性.py
```

脚本做六件事：

1. 报告 `类型`、`文档状态`、`故事线`、`时代`、`状态` 不在受控词表里的取值。
2. 报告缺少 `类型`、以及可引用的文档缺少 `文档状态` 的情况。
3. 报告仍写着 `分类` 的文档。
4. 报告 `故事线` 与路径矛盾的词条。判据按路径给出：故事目录下的词条只许本故事；`词条/参与者/`、`词条/概念/` 只许 `通用`（跨故事只留接口页）；`词条/地点/` 允许引用它的几条线。
5. 报告 `tags` 里的裸标签、不在 `主题/`、`核实/`、`来源/` 三组内的标签，以及主题不在词表内的取值。
6. 报告同名文件。跨故事同名按拆分规则允许，不报错；同一故事里出现两份同名才列出来，由人判断是否该合并。

脚本只报告，不改文件。改不改、怎么改由人决定。

## 迁移工具

两个一次性脚本留在 `工具/` 里，便于复核改法：

| 脚本 | 作用 |
|---|---|
| `迁移分类.py` | `分类` 退休，取值分流到 `类型`、`时代`、`tags`；`--fill-type` 按路径补 `类型` |
| `归一状态与时代.py` | `状态` 拆成 `状态` 与 `文档状态`，残留细节写进 `状态说明`；`时代` 换成受控取值 |
| `回填故事线.py` | `故事线` 去掉链接写法，按分支正文的实际引用与地点主线补齐。**改过分支正文的引用之后可以重跑**，用来复核归属有没有漂 |
| `修正属性.py` | 修 `类型` 判错、`_templates/` 未归为 `模板`、别名字段名、裸标签 |
| `补标签.py` | 把旧主题名并入词表，按篇挂母题。旧名到新名的映射写在脚本开头 |

两个脚本默认只报告，加 `--apply` 才写入。映射表写在脚本开头，逐条列出原值与去向，改口径就改表，不要改成按关键词猜测。
