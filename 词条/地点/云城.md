# 云城

## 概述
- **中文定名：云城**；**英文定名：Cloud City**（复数：**Cloud Cities**）。
- **敲定口径：** 英文即「云城邦联／Confederation of Cloud Cities」里的那个 **Cloud City**——不作另译、不另造专名。
- 云城是以云上人为主设计的真实空间站，同时是物质世界里的设施。站内从建造起就配建一批节点服务器，用于承载与服务云上世界与云上人。在[法厄同](法厄同/README.md)带上，各州由云城组成，多个云城依协议互联，构成[云邦](../../分支时间线/法厄同/词条/参与者/势力/云邦.md)。泰拉、卢娜、马尔斯也可以有云城，但不因此属于云邦。
- 官方全称「云城邦联」／**Confederation of Cloud Cities**（缩写 **CCC**）仅指法厄同带上的云邦，由本带各州的 Cloud City 组成。

## 定名

| 层级 | 中文 | 英文 |
|------|------|------|
| 单元 | **云城** | **Cloud City**（＝ CCC 全称中的 Cloud City） |
| 复数／网络 | 云城（网络） | **Cloud Cities** |
| 法厄同带协约体全称 | 云城邦联 | Confederation of Cloud Cities（CCC） |
| 法厄同带协约体简称 | 云邦 | Orbis |

### 用法
1. 设定文档、地图标注、英文对白中的单元名写 **Cloud City**。
2. 指法厄同带上组成云邦时，用复数 **Cloud Cities**（与 CCC 全称一致）。其它轨道的云城仍叫 Cloud City，但不因此属于云邦。
3. 不另造拉丁短名或其它英文别译——单元英文锁定为邦联全称中的 Cloud City。
4. 主体居民英文见 [云上人](../../分支时间线/法厄同/词条/参与者/族群/云上人.md)＝**Cloudtype**。

## 性质与结构
- **技术底座**：依托云上技术与服务器阵列；节点间以云上亚区块链等协议协同。
- **主体居民**：[云上人](../../分支时间线/法厄同/词条/参与者/族群/云上人.md)（Cloudtype）为管理与活动骨干。
- **人类起居**：早期只供云上人起居。扩张之后，一部分大型云城加入可供原生人起居的结构。这些原生人的权限仍低于云上人。
- **站内节点**：云城从建造起就配建一批节点服务器，节点承载与服务云上世界与云上人。云上世界的一个分区跑在这些节点上，云上人的活动也依赖它们。节点不是云城本身，也不能脱离云城单独存在——没有站，就没有电、没有散热、没有维护。

## 古早起源与构造（设定真相视角）

> 本段从旧文明、云上世界的最底层构造补述云城何以成为今天的形态。不替代或否定前节对政治—社会单元的定义，而是解释其背后的技术—世界观来源。详见概念词条：[信息海](../../分支时间线/法厄同/词条/概念/信息海.md)、[云上世界](../../分支时间线/法厄同/词条/概念/云上世界.md)。

旧文明构想世界的底层由规则与信息构成：信息聚成的纯粹维度即**信息海**，规则对信息施加影响、使其形成能够响应和产出的结构。旧文明以电子设备模拟这个构想，在模拟出的场域中注入数据与规则；再由更高级的智能按照规律而不只是规则处理问题，并以这些智能为脚手架，搭建了一个模仿现实世界的虚拟网络空间，即**云上世界**。

云上世界按云城分区。每座云城在云上世界中自成一个分区，分区跑在站内配建的节点服务器上；分区内的规则与规律由所在云城决定，不同云城可能不同，但彼此共享一套底层逻辑，使云上人在不同云城之间仍能被识别为同一人。灾前，协议相连且距离足够近的云城可以直接在电子设备之间传递云上人的实例。大灾变后，以太性质异变使这种通道不再稳定、不再安全，云上人的实例可能在传输中丢失或畸变，因此各云城不允许再用它运输云上人，转而重新使用物质世界的舰船把人连同其载体运往另一座云城。但简单信息或虚拟世界物品仍可在风险自负的前提下继续通过残破通道传递。

大灾变后，长距链路被以太乱流切断，各站退化为本地网络，统一的云上世界不再互通。底层逻辑仍在，云上人在不同云城之间仍能被接纳、仍能保持为人的形态。

> 圈内视角（如云上坟场的 A 站居民）通常不会以这种方式叙述云城。对他们来说，云城就是空间站、生活区与港口的集合。本节只在设定真相层使用。

## 与其他概念
- **[云邦](../../分支时间线/法厄同/词条/参与者/势力/云邦.md)**：仅法厄同带。由本带各州的云城组成的联合国式协约体（简称云邦／Orbis）。其它轨道的云城不归云邦管。
- **[云上坟场](../../分支时间线/法厄同/云上坟场/README.md)**：环带节点失联、碎片化与 A 站侧云城残部的微观叙述。
- **服务器独立／碎片化**：大天灾后航道切断、节点失联，许多云城被迫各自运转。法厄同的内战见环带大战；近地如何重组后续再议。
